# Deadlimit

Deadlimit — бесплатный open-source набор Windows-инструментов, который убирает
повторяющиеся ручные операции из пайплайна создания character-replacement модов
для Deadlock.

Он связывает рабочую папку художника, экспорт из 3ds Max, авторинг в Reduced
CSDK, компиляцию ресурсов, упаковку VPK и локальную установку в игру. Проект
развивается энтузиастами без SLA; обновления Deadlock и внешних программ могут
временно нарушать совместимость.

> Подготовка к публичному релизу ещё идёт. Portable-сборка и стабильный updater
> пока не опубликованы. Текущий запуск выполняется из Git-клона и требует
> .NET 10 SDK.

[English README](README.md)

## Состав проекта

- **Deadlimit Manager** — основное Windows-приложение: проекты, извлечение
  исходников, подготовка CSDK, онлайн-синхронизация, сборка, VPK и локальная
  установка.
- **Deadlimit Max Script** — вспомогательные инструменты 3ds Max для DMX и
  Vertex Color. Имена `DeadlimitPipelineScripts.ms` сохранены для совместимости.
- **Deadlimit Shade** — экспериментальные шейдеры и пресеты Substance 3D Painter.

Blender пока не поддерживается. Shade имеет экспериментальный статус; основной
фокус — Manager и Max Script.

## Проверенная среда

- Windows 11 x64
- Autodesk 3ds Max 2025
- Wall Worm 7
- Reduced CSDK 12
- актуальная Steam-установка Deadlock
- .NET 10 SDK для текущего запуска из клона

Точные версии внешних компонентов должны фиксироваться для каждого релиза.
Перед использованием другой версии проверьте [COMPATIBILITY.md](COMPATIBILITY.md).

Deadlimit не предоставляет коммерческие программы, доступ к игре или права на
чужой контент. Устанавливайте необходимые компоненты через их владельцев и
соблюдайте соответствующие лицензии и условия.

## Запуск из клона за пять минут

1. Установите Git и .NET 10 SDK.
2. Клонируйте репозиторий и запустите корневой launcher:

   ```powershell
   git clone https://github.com/downlimit/Deadlimit.git
   Set-Location Deadlimit
   .\DeadlimitManager.cmd
   ```

3. Откройте **Настройки** и укажите пути к установленным Deadlock, Reduced CSDK
   и другим инструментам. Автоматические действия с зависимостями скачивают
   сторонние файлы в локальные папки; перед запуском проверьте показанный источник.
4. Создайте или откройте проект Deadlimit. В его корне должны лежать рабочие DMX
   и соответствующие исходные текстуры.
5. Один раз выполните **ПОДГОТОВИТЬ ДЛЯ CSDK**, затем откройте CSDK для работы в
   ModelDoc и редакторе материалов.
6. **СОБРАТЬ И ТЕСТИРОВАТЬ** подготовит текущие входные файлы, скомпилирует
   изменения, восстановит необходимые данные модели, соберёт VPK и установит
   его в выбранный addons-слот локального Deadlock. Игра запускается отдельно.

Запущенный Deadlock блокирует загруженный VPK. Перед заменой архива Deadlimit
предложит закрыть клиент.

## Итерации в ONLINE CSDK

Зажмите **SHIFT** и нажмите **ЗАПУСК CSDK**: Deadlimit выполнит preserving
PREPARE, включит онлайн-синхронизацию и откроет CSDK. Повторный жест остановит
синхронизацию без запуска второго экземпляра CSDK.

В онлайн-режиме изменения поддерживаемых корневых DMX, текстур и необходимых
`*_vertexcolor.fbx` переносятся автоматически. Структурные изменения и новые
ссылки на материалы сами запускают полный preserving-PREPARE, оставляя CSDK
открытым. Ручная команда **ПОДГОТОВИТЬ ДЛЯ CSDK** нужна для восстановления, если
интерфейс сообщил об ошибке автоматической транзакции и сохранил предыдущий
рабочий content.

Ожидание Vertex Color sidecar включается только для renderable-меша DMX, чей
назначенный материал содержит `vertexcolor` в имени без учёта регистра, а
встроенный цвет недоступен. Посторонние DMX не ждут парный FBX.

## Граница пользовательского контента

Корень проекта остаётся рабочей зоной художника. Deadlimit хранит метаданные и
логи в скрытой папке `.deadlimit`, а CSDK/game-результаты создаёт в настроенных
локальных окружениях. Извлечённый `0source`, retail-ресурсы, скомпилированные
файлы Source 2 и VPK нельзя коммитить в этот репозиторий или прикладывать к issue.

## Разработка и вклад

```powershell
dotnet restore internal/src/Deadlimit/Deadlimit.csproj
dotnet build internal/src/Deadlimit/Deadlimit.csproj --configuration Release --no-restore
internal/tests/open-source-content-policy-smoke.ps1
internal/tests/portable-path-defaults-smoke.ps1
internal/tests/prepare-behavior-smoke.ps1
```

Правила fork/PR и обязательный DCO sign-off описаны в
[CONTRIBUTING.md](CONTRIBUTING.md). Английская документация является основной;
эта русская версия помогает пользователям пройти тот же рабочий путь.

Текущий `Deadlimit Updater` — Git-канал для разработчиков. Portable-канал уже
реализован, но пока не опубликован: один `Install-Deadlimit.cmd` загружает
GitHub Release assets с проверкой SHA-256, устанавливает программу в
`%LocalAppData%\Programs\Deadlimit` и создаёт ярлыки Manager/Update. Команда
`Update Deadlimit.cmd -Rollback` меняет местами текущую и предыдущую проверенные
установки.

Ранние portable beta-сборки планируются без цифровой подписи, поэтому Windows
SmartScreen может показать предупреждение о неизвестном издателе. Продолжайте
только для установщика или ZIP из официального GitHub Release
`downlimit/Deadlimit` при совпадении опубликованной SHA-256. При несовпадении
контрольной суммы не запускайте файл и сообщите об этом.
