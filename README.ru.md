# Deadlimit

**Моддинг character-replacement для Deadlock с меньшим количеством ручной возни с файлами и пересборками.**

Deadlimit — бесплатный open-source набор Windows-инструментов для художников, которые делают character-replacement моды для Deadlock. Он связывает файлы проекта, экспорт из DCC, работу в Reduced CSDK, компиляцию Source 2 ресурсов, упаковку VPK и локальную установку в игру в один рабочий процесс.

Модель, текстуры и дизайн Deadlimit за вас не сделает. Зато он берёт на себя значительную часть работы, где нужный файл должен оказаться в нужной папке в нужный момент.

## Начать отсюда

### Установка Deadlimit

Скачайте постоянный файл [`Install-Deadlimit.cmd`](https://github.com/downlimit/Deadlimit/releases/download/latest-main/Install-Deadlimit.cmd) и запустите его.

Установщик скачает последнюю успешную сборку `main`, проверит её, установит Deadlimit в `%LocalAppData%\Programs\Deadlimit`, создаст ярлыки Manager и Updater и запустит `DeadlimitManager.exe`.

**Git и .NET SDK для обычной установки художнику не нужны.**

Ранние сборки Deadlimit выпускаются без цифровой подписи, поэтому Windows SmartScreen может показать предупреждение о неизвестном издателе. Продолжайте только если установщик получен из официального релиза `downlimit/Deadlimit` и его SHA-256 совпадает с опубликованной контрольной суммой.

### Что понадобится

Сейчас проверенный рабочий набор выглядит так:

- Windows 11 x64;
- актуальная Steam-установка Deadlock;
- Reduced CSDK 12;
- Deadlimit Scripts в 3ds Max 2025;
- Wall Worm 7.36.2.

Точные проверенные версии, build Deadlock, snapshots внешних инструментов и известные ограничения собраны в [COMPATIBILITY.md](COMPATIBILITY.md). Deadlock и внешний инструментарий меняются часто, поэтому здесь мы не будем делать вид, что слово «актуальный» является номером версии.

Deadlimit не предоставляет коммерческие программы, retail-контент игры или доступ к сторонним сервисам. Получайте необходимые инструменты через их владельцев и соблюдайте соответствующие лицензии и условия.

## Что делает Deadlimit

Deadlimit Manager берёт на себя повторяющиеся части character-replacement пайплайна:

- хранит проекты художника в библиотеке;
- извлекает поддерживаемые исходные данные;
- подготавливает файлы проекта для Reduced CSDK;
- синхронизирует поддерживаемые файлы во время работы в CSDK;
- компилирует изменённые Source 2 ресурсы;
- восстанавливает данные модели, необходимые replacement-пайплайну;
- собирает результат в VPK;
- устанавливает его в настроенный локальный addons-слот Deadlock;
- проверяет обновления Deadlimit и поддерживает rollback.

Практический результат простой: меньше повторяющихся файловых операций между тестами и больше времени на сам мод.

## Три продукта Deadlimit

### Deadlimit Manager

Основное Windows-приложение. Управляет проектами, извлечением исходников, подготовкой CSDK, синхронизацией, сборкой, упаковкой, установкой, обновлениями и путями к локальным инструментам.

### Deadlimit Scripts

**Deadlimit Scripts**, также **Deadlimit Pipeline Scripts**, — DCC-инструменты для авторинга и экспорта DMX, Vertex Color и других частей Deadlock/Source 2 пайплайна.

Текущий встроенный модуль написан на MAXScript. Поддержка Blender запланирована в рамках того же продукта. Технический идентификатор `DeadlimitPipelineScripts.ms` остаётся в кодовой базе ради совместимости.

### Deadlimit Shade

Экспериментальная работа над шейдером и пресетами для Substance 3D Painter. Это часть проекта Deadlimit, но пока не готовый распространяемый production-инструмент.

Три продукта, один проект, и пока только один из них просит 3ds Max.

## Первый проект

1. Установите и откройте **Deadlimit Manager**.
2. Откройте **Settings** и укажите пути к retail Deadlock, Reduced CSDK и другим необходимым инструментам. Можно выбрать уже существующие установки; если для компонента доступно скачивание, оно запускается только явным действием пользователя.
3. Создайте или откройте проект Deadlimit. Его корень — рабочая зона художника для DMX и соответствующих исходных текстур.
4. Один раз выполните **PREPARE FOR CSDK**.
5. Запустите CSDK и продолжайте обычную работу в ModelDoc и редакторе материалов.
6. Когда нужна игровая сборка, используйте **BUILD & TEST**. Deadlimit подготовит текущие входные файлы, скомпилирует изменения, восстановит необходимые данные модели, соберёт VPK и установит его в настроенный локальный addons-слот.
7. Запустите Deadlock отдельно и проверьте результат.

Deadlock блокирует загруженный VPK. Если игра запущена в момент, когда Deadlimit нужно заменить архив, программа попросит сначала закрыть клиент. Это ожидаемое поведение, и момент для него игра обычно выбирает безошибочно.

## Быстрые итерации: ONLINE CSDK

Зажмите **SHIFT** и нажмите **LAUNCH CSDK**: Deadlimit выполнит preserving preparation, включит ONLINE CSDK синхронизацию и запустит CSDK. Повторите тот же жест, чтобы остановить синхронизацию без открытия второго экземпляра CSDK.

Пока ONLINE CSDK активен, поддерживаемые DMX из корня проекта, текстуры и необходимые изменения `*_vertexcolor.fbx` синхронизируются автоматически. Структурные изменения или изменения ссылок на материалы запускают полный preserving PREPARE, не закрывая CSDK.

Ручной **PREPARE FOR CSDK** в этом режиме нужен как recovery-действие, если интерфейс сообщил, что автоматическая транзакция завершилась ошибкой и сохранила последний рабочий content.

У SHIFT теперь ещё одна обязанность.

### Vertex Color sidecars

Ожидание Vertex Color sidecar применяется только к renderable DMX-мешу, назначенный материал которого содержит `vertexcolor` в имени без учёта регистра, а встроенный цвет недоступен. Посторонние DMX не ждут парный FBX.

Это правило не даёт свежему DMX попасть в обработку раньше Vertex Color файла, который должен экспортироваться вместе с ним.

## Где лежат ваши файлы

**Корень проекта** остаётся рабочей зоной художника. Метаданные проекта и логи Deadlimit хранит в скрытой папке `.deadlimit`.

Сгенерированные CSDK и game-результаты записываются в настроенные локальные окружения, а не обратно в репозиторий.

Не коммитьте и не прикладывайте к issue извлечённый `0source`, retail-ресурсы, скомпилированные Source 2 файлы или установленные VPK.

## Обновления и rollback

Каждый принятый merge в `main` после успешного CI автоматически публикуется в обновляемый канал `latest-main`.

`Update Deadlimit.cmd` скачивает последний проверенный пакет, обновляет программные файлы на месте, сохраняет `UserData` и оставляет предыдущую версию программы в `Backup`. `Update Deadlimit.cmd -Rollback` меняет текущую и резервную версии местами, не затрагивая пользовательские настройки и проекты.

Первая строка в **Settings** показывает установленную версию Deadlimit Manager и состояние обновления. Контекстная команда **CHECK** / **UPDATE...** использует тот же updater.

ZIP и checksum, видимые в rolling release, являются транспортными файлами установщика и updater. Ручная установка из ZIP не является отдельным поддерживаемым сценарием для художника.

## Для разработчиков

Если вы пришли сюда делать мод, на этом можно остановиться. Всё ниже относится к разработке самого Deadlimit.

### Запуск из клона

Установите Git и .NET 10 SDK, затем:

```powershell
git clone https://github.com/downlimit/Deadlimit.git
Set-Location Deadlimit
.\DeadlimitManager.cmd
```

### Сборка и smoke tests

```powershell
dotnet restore internal/src/Deadlimit/Deadlimit.csproj
dotnet build internal/src/Deadlimit/Deadlimit.csproj --configuration Release --no-restore
internal/tests/open-source-content-policy-smoke.ps1
internal/tests/portable-path-defaults-smoke.ps1
internal/tests/prepare-behavior-smoke.ps1
```

Полный Windows CI-контракт находится в [`.github/workflows/build.yml`](.github/workflows/build.yml). Правила fork/PR и обязательный DCO sign-off описаны в [CONTRIBUTING.md](CONTRIBUTING.md).

План готовности open-source проекта находится в [`internal/docs/OPEN_SOURCE_PLAN.md`](internal/docs/OPEN_SOURCE_PLAN.md).
