# Deadlimit

**Набор инструментов для художников, создающих моды для Deadlock.**

Deadlimit объединяет разрозненный пайплайн моддинга персонажей Deadlock в один понятный рабочий процесс: получить оригинальные игровые ресурсы, подготовить модель и текстуры, перенести их в Reduced CSDK, быстро итерироваться, собрать VPK и проверить результат в retail Deadlock.

Он берёт на себя рутинную часть Source 2-пайплайна, которая иначе сводится к ручному поиску по VPK, исправлению resource-путей, перекладыванию файлов между инструментами и повторению одних и тех же технических шагов после каждой правки.

**Бесплатно · Open source · Windows**

## Скачать

### Для художников

**[Скачать `Install-Deadlimit.cmd`](https://github.com/downlimit/Deadlimit/raw/refs/heads/main/Install-Deadlimit.cmd)**

Скачайте установщик и запустите его. Deadlimit установится в:

```text
%LocalAppData%\Programs\Deadlimit
```

Пользоваться Git или вручную настраивать .NET SDK не нужно. Если Git for Windows или .NET 10 SDK отсутствуют, установщик покажет, чего не хватает, и отдельно спросит разрешение на установку через WinGet.

Ранние сборки Deadlimit не подписаны цифровой подписью, поэтому Windows SmartScreen может показать предупреждение о неизвестном издателе. Запускайте только установщик, скачанный из официального репозитория `downlimit/Deadlimit`.

### Для разработчиков и контрибьюторов

Если вы хотите изменять сам Deadlimit, отправлять исправления или добавлять новые функции, клонируйте репозиторий через Git:

```powershell
git clone https://github.com/downlimit/Deadlimit.git
cd Deadlimit
.\DeadlimitManager.cmd
```

Для development checkout требуется .NET 10 SDK. Правила работы с репозиторием описаны в [CONTRIBUTING.md](CONTRIBUTING.md).

# Deadlimit Manager

**Deadlimit Manager** — основное приложение и центр рабочего процесса.

### Проекты

Каждый мод существует как отдельный проект Deadlimit. Manager хранит проекты в библиотеке и отслеживает выбранного персонажа, исходные файлы, подготовленный authoring-контент, Release ID и текущее состояние пайплайна.

### Получение оригинальных ресурсов

Вы выбираете персонажа Deadlock, а Manager получает из актуальной retail-версии игры поддерживаемые оригинальные ресурсы, необходимые как рабочая база.

Вместо ручного поиска по VPK, путям моделей, материалам и связанным ресурсам вы сразу получаете нормальную отправную точку для своего мода.

### Prepare for CSDK

Manager превращает авторские файлы в рабочее пространство для Reduced CSDK.

Он выполняет раскладку файлов, исправляет известные дефекты экспортёров и путей, подготавливает модель, создаёт необходимую material-структуру, связывает текстуры и выполняет другие Source 2-специфичные преобразования, которые иначе пришлось бы делать вручную.

Подготовленный проект остаётся полноценным редактируемым authoring-этапом. Его можно открыть в CSDK/ModelDoc, настроить материалы и шейдеры, сохранить эти изменения и продолжать работу. Deadlimit не пытается превратить художественный пайплайн в непрозрачную кнопку «сделать всё».

### Live Sync

CSDK можно оставить открытым во время работы.

Deadlimit отслеживает поддерживаемые изменения проекта и автоматически переносит их в подготовленную CSDK-версию. DMX, текстуры и Vertex Color можно обновлять без постоянного ручного цикла Prepare → Copy → Reopen. Если изменения затрагивают структуру проекта или ссылки на материалы, Deadlimit выполняет необходимый полный Prepare, не закрывая CSDK.

### Build & Test

Когда проект готов к проверке в игре, **Build & Test** выполняет release-часть пайплайна.

Deadlimit подготавливает актуальное состояние проекта, компилирует изменённые ресурсы Source 2, после компиляции восстанавливает необходимые animation bindings персонажа, проверяет результат, собирает addon в VPK и устанавливает его в выбранный локальный addons-слот Deadlock.

CSDK при этом остаётся именно authoring-этапом: animation bindings чинятся после компиляции, поэтому до финальной тестовой сборки художник может нормально работать с ModelDoc, материалами и шейдерами.

### Импорт и ремонт существующих VPK

Deadlimit может импортировать существующий `pak##_dir.vpk` как отдельный проект.

Compiled payload сохраняется и не прогоняется через обычный authoring compiler. Во время **Build & Test** Deadlimit может сравнить animation bindings моделей персонажей с актуальной retail-версией Deadlock, исправить устаревшие или отсутствующие bindings, пересобрать VPK, проверить его и установить обратно в принятый Release ID.

Этот режим намеренно решает конкретный класс проблем с animation bindings и не изображает универсальную кнопку ремонта любых возможных поломок мода.

### Управление инструментами

Manager собирает внешний modding toolchain в одном месте.

Он может найти и проверить установленный Deadlock, управлять Reduced CSDK и DeadlockTools, проверять состояние поддерживаемых инструментов и использовать вспомогательные утилиты вроде DepotDownloader, когда они нужны конкретному процессу.

# Deadlimit Scripts

**Deadlimit Scripts** — инструменты для этапа работы с моделью непосредственно в DCC.

Текущая встроенная реализация написана на MAXScript. Поддержка Blender запланирована в рамках того же продукта Deadlimit Scripts, а не как отдельный набор инструментов.

### Bone Tools

DMX-скелеты Valve после импорта не всегда удобно выглядят и ведут себя с точки зрения моделера.

Bone Tools позволяют подогнать визуальную длину и толщину костей под иерархию, развернуть отображение кости без изменения самого рига и восстановить совместимые кости, случайно превращённые в Editable Poly, сохраняя node identity, hierarchy, animation и Skin references.

### Vertex Color

Deadlimit Scripts упрощают работу с Vertex Color ещё до того, как модель попадёт в игру.

Можно переносить цвет между палитрой объектов и Vertex Color, включать и выключать отображение Vertex Color во viewport, распространять Vertex Color, материал и palette-данные между мешами, а поддерживаемые операции не требуют разрушать modifier stack.

Для раннего engine-preview Deadlimit Manager может подготовить материал, отображающий Vertex Color в CSDK.

Если DMX exporter теряет Vertex Color, **Export Vertex Color FBX** создаёт рядом companion-файл `*_vertexcolor.fbx`. Во время Prepare Manager автоматически находит sidecar и переносит Vertex Color обратно в соответствующий DMX-меш.

### Inner Lineart

**Inner Lineart** превращает характерный expanded-backface outline Deadlock в полноценный художественный инструмент внутри дизайна персонажа.

Вы выделяете нужные внутренние рёбра, задаёте ширину линии, а Deadlimit Scripts строит отдельную line-art геометрию с необходимым winding и направлением нормалей. При необходимости результат сохраняет UV, Vertex Color, material IDs, transforms и Skin исходной модели.

Так графичные линии можно закладывать непосредственно в дизайн модели, а не ограничивать характерный Deadlock line-art только внешним силуэтом персонажа.

# Deadlimit Shade

**В разработке.**

**Deadlimit Shade** — часть набора инструментов для художников по текстурам, работающих в Substance 3D Painter.

Его задача — сделать Painter полезным окном предварительного просмотра материалов персонажей Deadlock, чтобы художнику не приходилось оценивать текстуры через условный стандартный PBR viewport и узнавать реальный результат только после переноса в Source 2.

Текущий прототип уже включает Deadlock-oriented Painter shaders, профили персонажей, outline-preview инструменты, утилиты для анализа retail-материалов и текстур, а также Painter dock, который может применять Deadlimit preview setup к совместимому проекту.

Целевой путь выглядит так:

```text
Substance 3D Painter
        ↓
Deadlimit Shade
        ↓
Deadlimit Manager
        ↓
Deadlock
```

Цель — достоверный рабочий preview для принятия художественных решений, а не обещание pixel-perfect воспроизведения всего Source 2 renderer внутри Painter.

## Workflow

```text
Retail Deadlock assets
        ↓
Deadlimit Manager
        ↓
DCC + Deadlimit Scripts
        ↓
Substance 3D Painter + Deadlimit Shade
        ↓
Deadlimit Manager
Prepare / Live Sync / Build & Test
        ↓
Reduced CSDK
        ↓
VPK
        ↓
Retail Deadlock
```

Deadlimit Shade пока находится в разработке и не требуется для текущего model-authoring pipeline.

## Статус проекта

Deadlimit активно развивается вместе с постоянно меняющимся Deadlock / Source 2 ecosystem.

Windows — текущая поддерживаемая платформа. Текущая встроенная реализация Deadlimit Scripts написана на MAXScript, поддержка Blender запланирована, Deadlimit Shade находится в активной разработке.

Обновления игры и внешних инструментов могут требовать изменений пайплайна. Точные проверенные версии и актуальный статус поддержки находятся в [COMPATIBILITY.md](COMPATIBILITY.md).
